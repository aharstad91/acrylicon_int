**Date:** 2026-02-27
**Status:** FAIL
**Page(s) tested:** EN homepage, NO homepage, product page, reference single, reference archive, office page, locations, 404 pages, robots.txt, sitemaps

## Summary

The site has a **critical robots.txt blocking ALL search engine crawling** — a Servebolt staging default that was never replaced with a production robots.txt. This single issue prevents Google from indexing any page. Beyond that, sitemaps exist but contain dev pages and duplicate content, several pages have missing or incorrect meta descriptions, and HTML pages lack cache-control headers entirely.

## Issues Found

### Issue 1: robots.txt blocks ALL search engine crawling (CRITICAL)
- **Page:** `https://acryli-28355.jana-osl.servebolt.cloud/robots.txt`
- **Problem:** The robots.txt file contains Servebolt's default staging-site block:
  ```
  # This file is automatically added by servebolt.com to prevent
  # the pages in a testing or staging area to be indexed by robots.
  User-agent: *
  Disallow: /
  ```
  This tells ALL search engines to not crawl ANY page on the entire site. The file was auto-generated by Servebolt for staging environments and was never updated for production.
- **Impact:** **Total SEO blackout.** Google will not index any page. The site is effectively invisible to search engines. All other SEO work (schema, meta tags, hreflang) is meaningless until this is fixed.
- **Fix:** Replace `robots.txt` with a proper production version:
  ```
  User-agent: *
  Allow: /

  Sitemap: https://acryli-28355.jana-osl.servebolt.cloud/wp-sitemap.xml
  Sitemap: https://acryli-28355.jana-osl.servebolt.cloud/no/wp-sitemap.xml
  ```
  On Servebolt, this may require contacting support or changing the site's environment designation from "staging" to "production". Alternatively, create a physical `robots.txt` at the web root that overrides Servebolt's auto-generated one.
- **Priority:** **CRITICAL** — Must fix immediately. Nothing else matters until this is resolved.

### Issue 2: robots.txt has no Sitemap directive
- **Page:** `https://acryli-28355.jana-osl.servebolt.cloud/robots.txt`
- **Problem:** Even ignoring the `Disallow: /`, the robots.txt file contains no `Sitemap:` line. Google recommends declaring sitemap URLs in robots.txt to aid discovery.
- **Impact:** Medium — Google can still find sitemaps via Search Console, but automatic discovery is hindered.
- **Fix:** Add `Sitemap:` directives for both `/wp-sitemap.xml` and `/no/wp-sitemap.xml` when replacing the file (see Issue 1 fix).
- **Priority:** High (bundle with Issue 1 fix)

### Issue 3: EN product page meta description is in Norwegian
- **Page:** `https://acryli-28355.jana-osl.servebolt.cloud/products/flake-system-floor/`
- **Problem:** The EN product page has `<meta name="description" content="AcryliCon Flake System – Floor — Dekorativ overflate Sklisikring i ønsket gradering og metning For tung fottrafikk og moderat industri 2-3 mm tykkelse">`. This is Norwegian text on an `en-US` page. The multisite-sync plugin likely copied the NO description without translating it.
- **Impact:** Medium — Google may show Norwegian text in EN search results, confusing users and reducing CTR. May also signal quality issues to Google's language classifiers.
- **Fix:** Update the meta description for EN product pages to English translations. Check all synced EN pages for untranslated descriptions.
- **Priority:** High

### Issue 4: EN Locations page has NO meta description
- **Page:** `https://acryli-28355.jana-osl.servebolt.cloud/locations/`
- **Problem:** The page has `<title>Locations | AcryliCon</title>` but no `<meta name="description">` tag at all. Google will auto-generate a snippet from page content, which is often suboptimal.
- **Impact:** Low-Medium — Google can still index the page, but the SERP snippet will be unpredictable.
- **Fix:** Add a targeted meta description: "Find AcryliCon offices across Norway. Contact our local teams for seamless floor and wall solutions."
- **Priority:** Medium

### Issue 5: Sitemap exposes dev/internal pages
- **Page:** NO sitemap (`/no/wp-sitemap-posts-page-1.xml`)
- **Problem:** The sitemap includes pages that should not be indexed:
  - `/no/komponenter-under-utvikling/` — "Components under development" — a dev/staging page
  - `/no/forside/` — Duplicate of the homepage (`/no/`), with its own canonical URL, creating duplicate content
  - `/no/pamelding-til-nyhetsbrev/` — Newsletter signup, may be intentional but low SEO value
- **Impact:** Medium — Dev pages in the sitemap waste crawl budget and can appear in search results. The `/no/forside/` duplicate competes with `/no/` for ranking signals.
- **Fix:**
  - Set `/no/komponenter-under-utvikling/` to `noindex` or make it private/draft
  - Either redirect `/no/forside/` to `/no/` (301) or set it to `noindex` + update canonical to `/no/`
  - Consider excluding low-value pages from sitemap via `wp_sitemaps_posts_query_args` filter
- **Priority:** High

### Issue 6: Author/user pages exposed in sitemap
- **Page:** `/wp-sitemap-users-1.xml` (both EN and NO)
- **Problem:** The sitemap exposes 4 author archive pages at `/blog/author/{username}/`. These pages are accessible (HTTP 200) and expose usernames:
  - `andreasaharstad-no`
  - `hermanmaskinen-no`
  - `monika-acrylicon-no`
  - `mortenwebtekst-no`
  This is both an SEO quality issue (thin content pages) and a minor security concern (username enumeration).
- **Impact:** Low-Medium — Author pages with 1-4 posts each are thin content. Username exposure enables brute-force login attempts.
- **Fix:** Disable the user sitemap provider:
  ```php
  add_filter('wp_sitemaps_add_provider', function($provider, $name) {
      return $name === 'users' ? false : $provider;
  }, 10, 2);
  ```
  Also consider redirecting author archives to the homepage or returning 404.
- **Priority:** Medium

### Issue 7: Blog posts in EN sitemap are Norwegian content
- **Page:** `/wp-sitemap-posts-post-1.xml`
- **Problem:** 4 blog posts are in the EN sitemap but have Norwegian titles and content on `lang="en-US"` pages:
  - `Først ute med «Teknisk Godkjenning» for våtrom i industrien` (2017)
  - `AcryliCon Rogaland legger gulv i Asia` (2017)
  - `AcryliCons jubileumsgave fra Ekkubg Reitan` (2017)
  - `Et solid gulv er et godt fundament for alt vi driver med` (2020)
  These are Norwegian blog posts on the EN blog, served with `lang="en-US"`.
- **Impact:** Medium — Language mismatch signals confuse Google. These pages may rank for Norwegian queries but on the wrong language version, or may be demoted for language inconsistency.
- **Fix:** Either translate these posts to English, move them to the NO blog, or set them to `noindex`.
- **Priority:** Medium

### Issue 8: Product page URL redirects (slug mismatch)
- **Page:** `/no/produkter/flake-system/` and `/products/flake-system/`
- **Problem:** Both URLs 301 redirect to their actual slugs: `/no/produkter/flake-system-gulv/` and `/products/flake-system-floor/`. The `-gulv`/`-floor` suffix was apparently added after the original slugs were established. Any external links to the old URLs incur a redirect penalty.
- **Impact:** Low — The 301 redirects work correctly and pass link equity. But internal links should use the canonical URL directly to avoid the redirect hop.
- **Fix:** Audit all internal links to ensure they point to the post-redirect canonical URLs. Update any hardcoded links in templates or ACF fields.
- **Priority:** Low

### Issue 9: No Cache-Control headers on HTML pages
- **Page:** All HTML pages
- **Problem:** HTML page responses have no `Cache-Control` header at all. The only timing header is `X-Backend-Delay`. Without explicit cache headers, browser behavior is unpredictable and CDN/proxy caching won't work optimally.
- **Impact:** Low — TTFB is already excellent (20-30ms via Servebolt), but adding appropriate cache headers would improve repeat-visit performance and reduce server load.
- **Fix:** Add `Cache-Control: public, max-age=0, s-maxage=600, stale-while-revalidate=86400` for HTML pages. This allows CDN caching (10min) while browsers always revalidate.
- **Priority:** Low

### Issue 10: `/no/kontakt-oss/` returns 404
- **Page:** `https://acryli-28355.jana-osl.servebolt.cloud/no/kontakt-oss/`
- **Problem:** This URL (listed as a key page in the audit spec) returns HTTP 404. The contact/locations page may have been renamed or removed. The actual locations page appears to be at `/no/kontor/`.
- **Impact:** Medium — If any external links or old marketing materials point to `/no/kontakt-oss/`, those visitors hit a dead end.
- **Fix:** Create a 301 redirect from `/no/kontakt-oss/` to `/no/kontor/` (or wherever the contact content now lives).
- **Priority:** Medium
